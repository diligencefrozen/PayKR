# PayKR v0.2 — DB 검색과 2단계 캐시

기준: PayKR-rebuild-v0.1.zip / main 536d627 (기존 설정이 이후 변경되었으면 병합 검토).

## 적용
1. 기존 GitHub Desktop 프로젝트의 main을 Fetch/Pull하고, 변경사항이 없는지 확인한 뒤 별도 작업 브랜치를 만든다.
2. 패치 ZIP 안의 `PayKR-v0.2-patch` 폴더 **내용**을 기존 프로젝트 최상위 폴더에 덮어쓴다. `.git`, `.env`, `src/config/merchants.js`는 변경하지 않는다. 기존 파일을 삭제하지 않는다.
3. 선택: Node 22에서 `node scripts/check.mjs` 실행. PWA 자산 검사 실패 시 기존 브랜치와 차이를 확인한 뒤 `node scripts/pwa-assets.mjs`를 재실행한다.
4. 변경사항을 커밋하고 브랜치를 게시한 뒤 검토/병합한다. 초기 수집 Workflow와 SQL은 변경하지 않았으며 실행 중인 작업을 중단할 필요는 없다.
5. 전국 초기 수집 완료, delta 및 공간 RPC 검증 후 기존 `docs/SUPABASE-DEPLOY-KO.md` 절차로 DB 모드를 활성화한다. 이 패치는 활성화 설정을 변경하지 않는다.

## 동작
- 기존 카탈로그 캐시 유지. DB 검색용 L1 메모리 64 페이지, L2 IndexedDB 96 페이지 추가. 페이지 최대 61행. 같은 URL, 카탈로그 버전, 정확한 검색 조건과 페이지의 요청만 재사용한다. 유효기간 24시간, 빈 결과 10분, DB 장애 시 비어 있지 않은 결과만 최대 7일 이전 데이터로 표시한다. 오래된 결과는 안내 문구를 표시한다. 저장이 거부되면 네트워크 조회를 유지한다. 설정의 캐시 삭제는 두 종류의 캐시를 비운다.
- GPS 검색/직접 입력한 검색어/위치권한으로 시작한 세션의 지도 범위는 영속 캐시에 저장하지 않는다. 일반 지도 영역의 캐시에는 조회 영역과 결과가 로컬에 저장된다. 서버 캐싱이나 여러 이용자 간 공유 캐시는 아니다. 카카오 응답/비교 결과는 저장하지 않는다.
- DB 모드 전체/내 주변에서 현재 화면 범위의 모든 브랜드를 대상으로 60행씩 자동 조회한다. 10페이지(최대 600행)마다 멈추고 추가 결과가 있으면 더 보기를 제공한다. 전국 또는 밀집 지역의 모든 점포를 한 번에 내려받지 않는다. 카테고리 전체가 검색 대상이라는 것과 첫 600건에 모든 카테고리가 반드시 포함된다는 것은 다르다.
- DB 모드 전체 선택 시 현재 지도 위치와 줌을 유지한다. 기존 카카오 검색 모드의 동작과 내 주변 순회는 그대로 유지한다. 마커 클러스터링은 기존 KakaoProvider에 이미 있다.
- 실제 Java Hibernate ORM은 설치하지 않았다. 기존 정적 JS 구조에 Hibernate L1/L2 개념에 대응하는 캐시를 적용했으며 ORM/공유 서버 캐시는 아니다.
- 데이터 갱신은 기존 수집 방식 그대로다. 초기 수집 완료 전에는 DB 모드를 켜지 않는다. 새로운 수집 매핑, 폐업 구분, 예약 자동 초기수집, 자동 카카오 대조는 이번 패치 범위에서 제외한다.

## 검증과 제한
Node 22로 `node scripts/check.mjs`: 11개 테스트 묶음 및 정적 자산 확인 통과. 신규 테스트는 L1/L2 모의 저장소, 만료, 빈 결과, 중복 요청, 장애, 초기화, 전체 페이지와 카카오 0회 확인. 실제 브라우저 IndexedDB, 서비스 실환경 DB 검색/부하 테스트는 미수행. 정확한 지도 범위가 바뀌면 캐시 미스가 발생할 수 있으므로 실제 Egress 절감률은 운영에서 측정한다. 카카오 대조는 여전히 상세 화면 명시적 요청만 사용한다.
