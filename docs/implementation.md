# PayKR 2.0 구현 및 검증 기록

작업 대상은 기존 `develop`의 `6a88b0c`이다. 인수인계 문서가 지목한 아카이브 `5547d833`와 실제 체크아웃이 달라 이 비교에서는 실제 체크아웃을 기준으로 삼았다. 착수 시 작업 트리는 깨끗했고 원본의 `node tests/map-ui.test.mjs`와 `node tests/directory.test.mjs`가 모두 통과했다. 최종 로컬 검증일은 2026-11-28이다.

## 기존 UI에 추가한 기능

| 화면 | 기존 UI를 이용하는 방식 | 바로 쓸 수 있는 2.0 기능 |
| --- | --- | --- |
| 지도 | 둥근 검색창, 가로 카테고리 버튼, 기존 업종 아이콘·색과 위치 버튼 | 원주종합버스터미널 기본 위치, 자동 내 주변 검색, 현재 영역 재검색 |
| PC | 왼쪽 검색 패널과 오른쪽 지도 | 목록과 마커에서 같은 지점 상세 열기, 원문 주소 복사, 길찾기, 직원에게 보여줄 문장 |
| 모바일 | 검색창 아래 카테고리와 드래그 가능한 장소 시트 | 첫 화면의 목록, 선택을 유지하는 지도·목록 전환, 지도·온라인·가이드·더 보기 하단 탭 |
| 온라인 | 지도와 공통인 헤더·검색창·업종 버튼, 기존 브랜드 로고 카드 | 가로로 넘기거나 펼쳐서 업종 선택, 주문 시 결제 수단 확인 안내 |
| 공통 | PayKR 워드마크, 시스템·라이트·다크 테마 | 현재 언어로 페이지 이동, 설치·업데이트 안내, GitHub·Discord 의견 보내기 |

지도는 원주종합버스터미널에서 열리며, 위치 권한을 허용하면 현재 위치로 이동한다. 내 주변은 전체 오프라인 브랜드를 12개씩 자동으로 검색해 결과를 누적한다. 위치를 확인하지 못하면 원주에서 계속 탐색하거나 내 주변을 눌러 재시도할 수 있다. 전체 버튼은 원주종합버스터미널로 돌아간다. SDK 연결에 실패하면 자체 브랜드 목록을 이용할 수 있다. 지도와 더 보기에서 필독사항과 연도별 패치노트를 열 수 있다.

390px 화면에서 지도와 온라인 사용처의 검색창은 양쪽 여백 14px, 너비 362px, 높이 58px다. 1280px에서는 두 화면 모두 왼쪽 여백 16px, 너비 350px, 높이 58px다. 온라인 검색창과 업종 버튼은 목록을 스크롤해도 상단에 남는다. 높이가 500px 이하인 화면에서는 목록을 읽을 공간을 확보하기 위해 함께 스크롤된다. `tests/browser-ui.mjs`는 두 탭을 왕복하며 헤더와 검색창 위치를 비교하고, `tests/layout-compare.mjs`는 원본 지도 컨트롤과 온라인 로고 영역의 높이를 비교한다.

`ss/paykr2-*.png`에는 SDK 연결 실패 시의 실제 브랜드 목록 및 온라인 디렉터리 화면이 있다. 파일 이름에 `fixture`가 붙은 두 장은 브라우저 테스트용 장소 응답으로 지점 상세 화면을 연 결과다.

2026-11-28 작업 직전 커밋 `a4bacee`와 현재 온라인 사용처를 같은 Chromium 조건으로 세 번씩 비교했다. 로드한 JS 응답 본문은 55,746 B에서 58,016 B로 증가했고 최대 CLS는 양쪽 모두 0.00354 이하였다. 실제 LCP가 기록된 두 방문은 각각 548/116ms와 492/96ms였다. 외부 요청과 서비스 워커를 차단한 로컬 수치다. 자체 카탈로그 조회 40회의 냉간 p95는 12.5ms, L2 재방문 p95는 9ms였으며 후자의 원본 요청은 0회였다.

| `src/infrastructure/ads/`, `src/config/advertising.js` | 동의, 슬롯 중복 방지, 미충전·오류 처리, 공식 복구 태그 연결 지점을 관리한다. |

Spring MVC의 책임 분리와 Hibernate의 세션별 Identity Map·공유 캐시 개념을 브라우저 ES 모듈로 구현했다. 단일 지점마다 API를 재호출하지 않고 일괄 응답을 매핑한다. `forum/`의 이전 OAuth·포럼 소스와 설정은 보존했다. 과거 세 개의 전역 진입 스크립트 `main.js`, `online.js`, `i18n.js`는 ES 모듈이 대체한다.

## 데이터와 캐시 정책

장소 검색 163개 카테고리 연결은 160개 브랜드로 정규화했다. 이니스프리, ABC마트, 식자재왕도매마트에 각각 두 카테고리 연결이 있다. 원본의 검색어 철자와 36개 온라인 항목·별칭·로고를 유지했다. 온라인 목록에는 원래 판매처별 URL이나 웹·앱별 검증일이 없었다. 과거 목록 시점, 현재 카탈로그 조회 시각과 실제 결제 확인 날짜를 구분한다.

| 저장소 | 데이터와 범위 | 한도·갱신 |
| --- | --- | --- |
| L1 엔티티 | 탭 안의 자체 매장·온라인 카탈로그와 정규 ID별 레코드 | 영역 2개, 5분 TTL. L2 원래 만료 시각도 적용 |
| L1 쿼리 | 버전·목록·카테고리·정규 검색어에 대응하는 ID 배열 | 최대 64개, 2분 TTL, LRU. 자유 입력은 메모리에만 존재 |
| L2 IndexedDB | 프로젝트 경로와 오리진별 자체 엔티티, 전체·카테고리별 ID 색인 | 두 스냅샷, 24시간. 콘텐츠 해시 변경 시 원본에서 재구성. 엔티티와 색인을 함께 커밋 |
| Kakao | 열린 화면의 응답, 마커, 진행 중인 동일 요청 | L2·서비스 워커 저장 제외. 키에 실제 bounds와 페이지를 포함. 최대 4개 동시 요청, 카테고리당 한 번에 12개 키워드, 자유 검색은 요청당 15개·최대 3페이지 |
| 서비스 워커 | 무결성 해시가 있는 동일 오리진 앱 셸·번역·가이드·자체 정적 자산 | 탐색은 네트워크 우선, 실패 시 설치된 버전 제공. 요청 URL의 개인 검색어를 캐시에 쓰지 않는다. 광고·CMP·Discord·OAuth·지도 응답 제외 |

저장 제한·할당량 실패 시 메모리와 원본 조회를 사용한다. 저장된 카탈로그 삭제는 BroadcastChannel 또는 storage 이벤트로 다른 탭에 알린다. IndexedDB 트랜잭션에서 무효화 번호를 검사해 삭제 전 시작한 다른 탭의 응답이 저장소를 되살리는 상황을 막는다. 캐시를 모든 방문자가 공유하는 서버는 없다.

## 성능 측정

Windows Chromium, 390 × 844, 로컬 `/PayKR/` 온라인 페이지의 `?lang=en&adpreview=1`에서 같은 스크립트로 전후를 비교했다. 각 3회 탐색, 외부 요청 및 SW 차단, 실제 광고 미사용 조건이다. JS는 전송 압축 전 응답 본문 크기다. 첫 탐색에서 LCP 샘플이 나오지 않아 0ms 기록은 제외했다.

| 온라인 페이지 | 기존 `6a88b0c` | 2.0 비교 실행 |
| --- | ---: | ---: |
| 로드한 JS 본문 합계 | 24,203 B | 53,800 B |
| CLS 3회 중 최대 | 0.1230 | 0 |
| LCP 감지된 두 샘플 | 140 / 112 ms | 344 / 64 ms |
| 3번째 탐색 시 JS 힙 | 4.47 MB | 4.80 MB |

새 기능으로 초기 JS와 힙이 증가했다. 로컬 LCP 편차가 커서 개선 달성을 판단하지 않았다. 광고 미리보기 공간을 예약하고 초기 HTML에 카드와 번역을 포함해 테스트의 레이아웃 이동을 줄였다. 운영 INP·LCP·CLS 75백분위, 실제 지도·광고가 포함된 방문, 광고 수익은 측정 대기다.

같은 2.0 저장소에서 자체 매장 카탈로그 검색을 조건별로 40회 측정했다. 아래 값은 캐시 정책의 효과이며 기존 온라인 페이지도 필터 입력 때마다 외부 API를 호출하지 않았다.

| 자체 카탈로그 | 원본 요청 | L1 / L2 적중 | p50 / p95 |
| --- | ---: | ---: | ---: |
| 매번 비운 냉간 조회 | 40 | 0 / 0 | 9.0 / 12.9 ms |
| 같은 탭에서 반복 | 0 | 40 / 0 | 둘 다 타이머 분해능 이하 |
| L1을 새로 만든 재방문 모사, 실제 IndexedDB | 0 | 0 / 40 | 1.1 / 2.3 ms |

저장 스냅샷 JSON은 24,801 B였다. 동시 동일 조회 10건은 원본 호출 1회와 병합 9건이었다. 기존 지도에서 전체 선택 시 163개 검색을 즉시 발행하던 경로는 첫 12개를 최대 4개씩 처리한다. 이후 묶음은 사용자가 추가 조회한다. 이는 동일 결과 전부를 첫 화면에 표시하는 속도 비교가 아니다.

## 검증과 남은 출시 조건

- `node scripts/check.mjs --browser --screenshots`로 검색·필터·선택·주소, 데이터·번역·광고·캐시, 실제 Chromium의 서로 다른 탭 간 무효화, 구 스키마 마이그레이션, 서비스 워커 설치와 오프라인 직접 진입·재연결을 확인했다. 설치 거부, 업데이트 승인, standalone, iOS 설치 안내는 브라우저 이벤트 목으로 확인했다.
- `tests/layout-compare.mjs`는 `PAYKR_BASELINE_ROOT`에 지정한 원본 추출본과 같은 뷰포트에서 측정한다. `tests/browser-perf.mjs`도 이 변수를 지원한다. 새 버전을 측정할 때 변수를 해제한다. `tests/performance.mjs`는 실제 Chromium IndexedDB를 사용한다.
- 다섯 사전의 전체 키와 치환 변수, 초기 HTML, URL·저장값·브라우저 언어 우선순위, zh 지역·스크립트와 레이아웃을 검사했다. 다섯 언어 모두 외부 원어민 편집 검수는 대기 중이다.
- 2026-11-28 로컬 미리보기 `http://127.0.0.1:8792`에서 카카오 SDK가 HTTP 401 `domain mismatched`를 반환했다. 화면 구조·GPS·검색 동작은 Chromium에서 테스트용 SDK로 확인했다. 실제 지도 타일과 실기기 위치 승인은 도메인 등록 후 확인해야 한다.
- 실제 iOS Safari 홈 화면 추가, Android 설치·업데이트, 스크린리더와 실사용 접근성 감사, 지역별 CMP·공식 복구 메시지·AdSense 단위·수익, 인증된 Discord 전송 및 운영 브랜치의 새 이슈 양식은 미검증이다. 공개 저장소에서 Issues 활성화와 목록 응답은 확인했다.
- 외부 계정·도메인·지도 키·유료 인프라와 운영 배포를 변경하지 않았다. AdSense·CMP·복구 설정과 정책 근거는 [운영 검토 문서](policy-review.md)에 있다. 위치의 국내 판별은 [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/)의 일반화된 1:50m 해안선 데이터를 사용한다.
